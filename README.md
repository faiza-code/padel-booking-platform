# منصة حجز ملاعب البادل 

منصة إلكترونية لحجز ملاعب البادل، تتكون من لوحة تحكم للإدارة وواجهة للعميل بدون تسجيل دخول.

## الهيكلة

```
├── backend/     منصة الـ API (.NET 8)
└── frontend/    واجهة الويب (React)
```

---

## التقنيات المستخدمة

### الباكند
- **.NET 8** (ASP.NET Core Web API)
- **Entity Framework Core** + **SQL Server**
- **JWT** لمصادقة لوحة التحكم
- تكامل **بوابة ثواني (Thawani)** للدفع الإلكتروني (Sandbox)
- هيكلة طبقية: Domain / Application / Infrastructure / Api

### الفرونت اند
- **React 18** + **Vite**
- **React Router** للتنقل
- **Axios** للاتصال بالـ API
- تصميم مخصص (RTL / عربي بالكامل)

---

## خطوات التشغيل

### 1. الباكند (.NET API)

المتطلبات: .NET 8 SDK، SQL Server (أو LocalDB)، Visual Studio 2022 (أو أي محرر مع دعم .NET).

```bash
cd backend
```

افتح `PadelBooking.sln` في Visual Studio.

عدّل ملف `src/PadelBooking.Api/appsettings.json` حسب الحاجة:
- `ConnectionStrings:DefaultConnection` — إذا تستخدم LocalDB، القيمة الحالية تعمل مباشرة. إذا تستخدم SQL Server كامل، عدّل اسم السيرفر.
- `Thawani:SecretKey` و `Thawani:PublishableKey` — مفاتيح بوابة ثواني (Sandbox). **ملاحظة**: القيم الحالية placeholders؛ الدفع الإلكتروني يتطلب حساب تاجر تجريبي حقيقي من ثواني لاختباره فعليًا (راجع قسم الملاحظات بالأسفل).

من **Package Manager Console** (Tools → NuGet Package Manager → Package Manager Console)، تأكد إن Default project = `PadelBooking.Infrastructure`، ثم نفّذ:

```powershell
Update-Database -Project PadelBooking.Infrastructure -StartupProject PadelBooking.Api
```

هذا ينشئ قاعدة البيانات وجميع الجداول تلقائيًا (Migrations متضمنة بالمشروع).

بعدها، اجعل `PadelBooking.Api` هو Startup Project واضغط **F5** لتشغيل السيرفر. يفتح تلقائيًا على صفحة Swagger على المنفذ `https://localhost:7080`.

عند أول تشغيل، ينشئ النظام تلقائيًا حساب إدارة افتراضي (راجع بيانات الدخول بالأسفل).

### 2. الفرونت اند (React)

المتطلبات: Node.js 18 أو أحدث.

```bash
cd frontend
npm install
npm run dev
```

افتح المتصفح على `http://localhost:5173`.

**مهم**: تأكد إن `src/api/client.js` يحتوي على نفس منفذ الـ API الخاص بك:
```js
export const API_BASE_URL = "https://localhost:7080/api";
```

يجب أن يكون الباكند شغالاً بنفس الوقت حتى تعمل الواجهة.

## بيانات الدخول للوحة التحكم

عند أول تشغيل للباكند، يُنشئ النظام تلقائيًا حساب إدارة افتراضي:

| الحقل | القيمة |
|---|---|
| اسم المستخدم | `admin` |
| كلمة المرور | `Admin@12345` |

الرابط: `http://localhost:5173/admin/login`

يمكن تغيير بيانات الحساب الافتراضي من قسم `Admin` في `appsettings.json` **قبل** أول تشغيل للسيرفر (بعد إنشاء الحساب الأول، التغيير هنا لا يؤثر إلا بحذف الصف يدويًا من جدول `AdminUsers` وإعادة التشغيل).

## نقاط مهمة حول آلية العمل

- **واجهة العميل** (`/`) لا تتطلب تسجيل دخول، ولا تعرض اسم الملعب المخصص للعميل أبدًا (يُختار عشوائيًا من بين الملاعب المتاحة عند التأكيد).
- **التسعير** يُحتسب تلقائيًا حسب شرائح الأسعار المعرّفة لكل ملعب بناءً على عدد ساعات الحجز.
- **حجز واحد** يمكن أن يشمل عدة فترات وحتى عدة أيام مختلفة ضمن نفس العملية.
- **فحص التوفر** يُعاد التحقق منه لحظة التأكيد الفعلي (وليس فقط لحظة العرض) لمنع تعارض الحجوزات، داخل معاملة قاعدة بيانات واحدة (Transaction).
- **الدفع عند الوصول** يعمل بالكامل. **الدفع الإلكتروني عبر ثواني** منفّذ تقنيًا بالكامل (إنشاء جلسة دفع + تأكيد الدفع)، لكنه يتطلب مفاتيح Sandbox حقيقية من حساب تاجر مسجّل لدى ثواني لاختباره عمليًا؛ الكود جاهز ويعمل فور توفر المفاتيح.

## ملاحظات إضافية

- بنية المشروع الخلفي تتبع Clean/Layered Architecture لتسهيل الصيانة والتوسع.
- تم اختبار تدفق العمل الكامل (إنشاء ملعب → ضبط ساعات العمل → عرض التوفر → الحجز → عرضه بلوحة التحكم) وهو يعمل من طرف لطرف.
- عند تشغيل المشروع لأول مرة على جهاز جديد، تأكد من تطابق منفذي الباكند والفرونت اند في كل من `launchSettings.json` (الباكند) و `client.js` (الفرونت اند).
